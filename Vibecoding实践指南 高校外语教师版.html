⬢安装 Node.js

ℹ️
为什么需要 Node.js？
大多数你能做的教学网页工具都依赖 Node.js 运行。把它理解为"让你的电脑能跑网页程序的引擎"。只需安装一次，以后不用管它。
下载安装包
访问 nodejs.org/zh-cn ↗，点击左边绿色按钮（LTS 长期支持版）。
一路点"下一步"安装
全部默认选项，点击"下一步"直到完成。中间可能会弹出一个黑色命令窗口自动运行，等它结束就好。
验证安装成功
在终端输入以下命令：
验证命令
node --version
如果显示 v20.x.x 这样的版本号，说明安装成功 ✅
⚠️
常见问题：命令没有反应 / 提示"不是内部或外部命令"
关闭所有窗口，重新打开终端再试。如果还不行，把错误信息截图发给 AI IDE 的对话框。

验证安装成功

python --version
显示 Python 3.x.x 即成功 ✅。macOS 用户如果看到 Python 2.x，改用 python3 --version。

⬡ Part 1

生存技能

遇到报错不要慌。这里教你看懂报错、处理环境问题，以及建立"遇到问题先问 AI"的工作习惯。

🔍读懂报错信息

点击下面每条报错，查看原因和解决方法。红色文字是报错类型，直接在 AI 对话框里复制粘贴即可求助。

ModuleNotFoundError 找不到模块（Python 最常见） ▼
📍 原因：你用的某个 Python 库还没安装。比如用了 `import requests` 但没装过。
✅ 解决：在终端运行 pip install 库名，例如 pip install requests。如果还不行，把完整报错贴给 AI。
Cannot find module 找不到模块（Node.js 版） ▼
📍 原因：项目缺少依赖包，通常是因为从别处复制项目后没安装依赖。
✅ 解决：在项目目录下运行 npm install，它会自动安装所有需要的包。
SyntaxError 语法错误 ▼
📍 原因：代码格式有问题——少括号、多冒号、缩进不对。AI 生成的代码偶尔也有笔误。
✅ 解决：把报错信息和行号一起复制给 AI，说"第 X 行有语法错误，帮我修复"。
TypeError 类型错误 ▼
📍 原因：对不兼容的数据类型做了操作，比如对 `None` 调用方法，或把字符串当数字用。
✅ 解决：复制完整的 traceback 给 AI，让它修复逻辑。
ECONNREFUSED 网络连接失败 ▼
📍 原因：程序尝试访问网络服务但连不上。可能是目标服务器挂了、代理问题、URL 写错。
✅ 解决：先确认能正常上网。如果是调用 API，检查 URL 和代理。告诉 AI："我的网络环境在国内，帮我检查是否需要配置代理"。
401 Unauthorized API Key 认证失败（你大概率会遇到！） ▼
📍 原因：API Key 无效、未配置、或拼写错误。这是你接触 AI 工具开发遇到的第一道真坎。
✅ 解决步骤：
1. 检查 Key 是否正确复制（无多余空格）
2. 检查环境变量是否设置成功（终端输入 echo $DEEPSEEK_API_KEY 或 echo %DEEPSEEK_API_KEY%）
3. 如果为空，说明没配好——让 AI 帮你配置
4. 去 DeepSeek 平台确认 Key 是否还有余额

📁文件和路径的基本认知

📂 绝对路径
从根目录开始的完整地址。
Windows: C:\Users\张老师\Desktop\project\index.html
Mac: /Users/zhang/project/index.html
就像"中国北京市海淀区XX路XX号"——不会搞混，但很长。
📍 相对路径
相对于当前文件的位置。
./index.html = 同目录下
../data/file.csv = 上级目录的 data 文件夹里
就像"隔壁那栋楼"——简单，但取决于你在哪。

🔐环境变量：API Key 的保险箱

🏦 保险箱比喻

API Key 是你的银行卡密码。

❌ 写在代码里 → 就像把密码贴在便利贴上，贴在银行卡上到处给人看。一旦分享代码，密码就泄露了。

✅ 存在环境变量里 → 就像把密码放进保险箱。程序需要用密码时自己去拿，但密码永远不会出现在纸上（代码里）。

⬡ Part 2

提示词宝典

把教学问题翻译成 AI 能理解的精准指令。这不是"跟机器说话"，是"让懂代码的助教明白你的需求"。

🔄从"教学想法"到"AI 指令"

很多老师把 AI 当搜索引擎：问一个问题，得到一个答案，结束。但 AI 的真正力量在于多轮对话——你说需求、AI 实现、你判断、AI 修改，循环迭代直到满意。

❌ 搜索引擎式用法 vs ✅ 迭代式用法

❌ "帮我做个词汇测试" → AI 随便给了一个 → 不满意 → 放弃

✅ "帮我做个词汇测试" → AI 给了一个 → "把难度调到四级水平，每题4个选项，加上中文释义" → AI 改了 → "再加个计时功能和得分统计" → 完美！

🧰四大核心技巧

🎭 角色设定
告诉 AI"你是谁"。
示例：
"你是一名有 10 年经验的高校英语教师，擅长四级备考辅导。"
📐 输出控制
告诉 AI"你要什么格式"。
示例：
"请用 JSON 格式输出，包含 question、options、answer 三个字段。"
📋 少样本提示
给 AI 一个例子，让它照着做。
示例：
“我给你一个例句和对应的题目……请按照这个格式，为下面的句子出题。”
🔗 思维链
让 AI 一步步思考。
示例：
"让我们一步步思考：首先确定文本难度，其次找出语法点，最后针对每个语法点设计题目。"

🔁多轮迭代的正确姿势

第 1 轮：说清需求
"我需要一个英语听力理解题自动生成工具，输入一段听力原文，自动生成 5 道选择题，难度对应四级水平。"
第 2 轮：具体调整
"很好，但选项太容易区分了。干扰项要更接近正确答案，考查学生对细节的理解。每题加上解题思路。"
第 3 轮：功能扩展
"现在帮我加一个功能：生成后可以一键导出为 Word 文档，方便打印给学生。"
第 N 轮：直到满意
每次只提一个改进点，让 AI 专注解决。不要一次提五个修改需求，容易互相干扰。

    不怕改坏、不怕丢文件——让 AI 帮你管好每个版本

    📄 写论文时你一定经历过……

    版本控制（Git）就是帮你自动管理这些版本的"时光机"——它像摄像机一样记录每次修改，随时可以回到任意版本，还能同时尝试不同方向，而不用担心搞乱原稿。

    ⏰什么时候需要版本控制？

    📦 场景一：开始一个新项目时

    当你新建了一个教学工具项目，先让 AI 完成初始化。这样后续每次修改都会被记录下来，就像给项目装上了"监控摄像头"。

    ⬡ Part 7 · 工程化实践

    代码审查：让 AI 给你的工具"体检"

    AI 写的代码不一定完美——用 AI 来审查 AI，双重保险

    📄 就像论文投稿前要校对一样……

    你写完一篇论文，一定会通读几遍，检查语法错误、逻辑漏洞，可能还会请同事帮忙校对。代码也是如此——AI 帮你写完了工具，但它也可能有"错别字"（逻辑缺陷）或"病句"（性能隐患）。

    代码审查（Code Review）就是请 AI 自己当"校对员"，重新审视它写出来的代码。这件事不需要你懂任何编程知识——你只需要告诉 AI "帮我看一下"，剩下的它来完成。

    最妙的是：你完全不需要看懂代码，只需要把 AI 给你的审查报告读一遍，像读体检报告一样了解"哪里需要注意"就够了。

    🎯
    核心原则

    代码审查不是让你去学代码，而是让 AI 当你的"翻译"——你把需求说给 AI，AI 去检查代码，再把结果用中文告诉你。你要做的只有一件事：在合适的时机，说出合适的话。

    ⏰什么时候需要代码审查？

    🩺 场景一：完成工具后全面体检

    当你用 AI 完成了一个教学工具，它看起来运行正常，但你心里没底——"这代码到底写得行不行？"就像买了新车去做个全面检测，代码也需要全面检查才能放心用。

    💬 告诉 AI 的话（复制后按需修改）🌱 零基础
    我刚完成了一个教学工具，项目在 [项目路径]。我完全不懂编程，请你帮我做一次全面的代码审查：1）代码里有没有明显的问题或 bug？2）功能实现得是否稳定可靠？3）有没有什么潜在风险？请用简单的语言告诉我结果，就像给一个完全外行的人解释那样。
    方括号部分替换为你的项目路径
    🔒 场景二：担心数据安全

    如果工具涉及学生的姓名、学号、成绩等敏感信息，安全是第一位的。让 AI 当一次"安全审计员"，帮你找到可能泄露数据的漏洞——就像检查家里的门窗有没有关好。

    💬 告诉 AI 的话（复制后按需修改）🌿 简单概念
    这个工具会存储学生的姓名、学号和成绩数据。请你检查一下安全性：1）这些数据存储得安全吗？会不会被别人看到？2）数据在传输过程中有没有被泄露的风险？3）有没有学生隐私泄露的隐患？如果有安全问题，请告诉我具体怎么修，用最简单的步骤说明。
    涉及学生数据时，这一步非常重要
    ⚡ 场景三：担心多人同时使用会卡

    一个工具在你自己电脑上用得很流畅，但课堂上 40 个学生同时访问呢？提前找出性能瓶颈，避免上课时"翻车"——就像在活动开始前检查场地能不能容纳所有人。

    这个工具预计在课堂上会有 30-50 个学生同时使用。请帮我检查代码性能：1）多人同时访问时会不会变慢或崩溃？2）有没有哪些代码写得比较"重"会影响速度？3）哪些地方是性能瓶颈？请按重要程度排序，告诉我先优化什么、后优化什么。
    如果学生人数更多，可以修改数字

    ⬡ Part 7 · 工程化实践

    代码质量：解耦与鲁棒

    教学工具不怕改、不怕"乱用"

    📄 就像模块化备课一样……

    你把一学期的课程写成独立的章节课件，想改第三章内容时，完全不影响第五章。好的代码也是这样，每个功能都是独立的"章节"，修改一个功能不影响其他功能。

    而不解耦（耦合）的代码就像把所有内容写在一个大文档里，想改第三课就得翻遍整个文档，生怕改错其他地方。

    解耦（模块化）就是把混在一起的功能分开，让每个功能独立、互相不影响。你不需要懂技术原理，只需要在适当的时候告诉 AI 去做这件事。

    🎯
    核心原则

    解耦不是为了写"漂亮代码"，而是为了让你改起来不害怕。当你发现"改一个地方，别的地方跟着出问题"时，就是需要解耦的信号。你不需要知道怎么做——把问题告诉 AI 就好。

    🔧什么时候需要"解耦"？

    🔍 场景一：改一个功能前，先看有没有"连锁反应"

    你想给教学工具的"词汇测验"功能增加一个计时器，但不确定这个修改会不会影响到旁边的"听写"功能。就像一个老师想调整第三章的练习题，但担心会不会打乱第五章的知识点安排——先检查清楚再动手。

    💬 告诉 AI 的话（复制后按需修改）🌱 零基础
    我想给工具的"词汇测验"功能加上一个计时器。但我担心这个修改会影响其他功能。请帮我检查一下：词汇测验和其他功能（特别是听写、单词列表）之间有没有共用的代码？如果加计时器，会不会影响其他功能的正常运行？请用简单的语言告诉我，哪些地方需要注意。
    把"词汇测验"换成你要改的功能名称
    ✂️ 场景二：功能混在一起分不开——拆！

    你发现 AI 写的代码里，"词汇测验"和"成绩统计"两个功能好像揉在一起了——每次改测验的得分规则，成绩统计的显示也变了。就像你在一个文档里同时写教案和学生活动说明，想改教案却发现学生活动也被改乱了——需要把它们分开。

    💬 告诉 AI 的话（复制后按需修改）🌿 简单概念
    我发现"词汇测验"和"成绩统计"这两个功能好像混在一起了，每次改测验规则，成绩统计也会跟着变。请帮我把它们拆开，让每个功能独立：1）词汇测验只管考试和判分；2）成绩统计只管统计和显示分数。拆完之后请告诉我以后怎么单独修改其中一个而不影响另一个。
    描述清楚哪两个功能"纠缠"在一起

    🛡️鲁棒（健壮性）：工具不怕"乱用"

    📄 就像课堂应变能力一样……

    教学设计只考虑了"标准学生"的反应，遇到学生提出意想不到的问题就手足无措。一个"鲁棒"的课堂设计，无论学生问什么你都能从容应对。

    代码的鲁棒性也一样：不管使用者怎么操作、输入什么奇怪内容，工具都能正常运行而不是崩溃。学生乱写答案、网络突然中断、一次导入上千个单词——好的工具应该经得起这些"折腾"。

    做鲁棒性优化，就是让 AI 给你的工具穿上"防弹衣"——不用你懂程序怎么防御，只需要告诉 AI 你在担心什么。

    🎯
    核心原则

    鲁棒性不是让代码"扛住所有攻击"，而是让你的工具在最差情况下也能优雅应对。你不需要考虑所有边界情况——把你能想到的"万一……怎么办？"告诉 AI 就够了。

    📝 场景一：学生乱写、交空内容、输入火星文

    你的在线测验工具做好了，但你担心：学生不填答案直接提交怎么办？在姓名栏输入表情符号怎么办？在作文框里随便敲键盘乱码怎么办？就像上课时你遇到学生给出各种意想不到的回答，工具也需要"提前备课"来应对这些情况。

    💬 告诉 AI 的话（复制后按需修改）🌱 零基础
    我的在线测验工具，学生可以提交填空题答案和作文。请你帮我检查一下：如果学生什么都不填就提交、或者在输入框里输入特殊符号和表情、或者输入特别长的内容，程序会不会崩溃或报错？如果有问题，请帮我加上检查，让工具在这些情况下也能正常运行并给出友好的提示。
    把具体的输入类型告诉 AI，它会针对性地检查
    🌊 场景二：突然断网、海量数据、特殊字符

    课堂上有 50 个学生同时提交作业，系统会不会卡死？单词本的 CSV 文件里有中文和日文字符，能不能正常显示？学生做到一半突然断网，已答的题目会不会丢失？这些"边界情况"就像课堂上的突发状况——提前想好预案，上课时才不会手忙脚乱。

    💬 告诉 AI 的话（复制后按需修改）🌿 简单概念
    我的工具会有这样的使用场景：1）大约 30-50 个学生同时使用；2）学生导入的单词文件可能包含中文、日文或特殊符号；3）学生的网络可能不稳定，中途断线。请帮我检查代码有没有考虑到这些情况，如果有遗漏请帮我加上保护措施。特别关注：大量数据会不会卡、特殊字符会不会乱码、网络中断会不会丢数据。
    把你实际遇到的情况替换进去，越具体越好

    你不需要跟 AI 说"请解耦"或"请提升鲁棒性"——直接说你的担心就好：

  • →"万一突然断网会丢数据吗？" → AI 帮你处理边界情况

    • 你只需要把真实的使用场景和担心说清楚，AI 自然会帮你把代码变得更"扛造"。你发现什么问题，AI 就解决什么问题——这就是工程化实践的精髓。

    部署与分享：让学生用上你的工具

    把做好的教学工具发布到互联网，生成一个链接，发给全班同学

    📄 就像把课件上传到网盘分享给学生……

    你做好了一份精美的课件，想分享给学生——可能是发到课程群、上传到学习平台，或者生成一个链接让他们随时查看。

    部署（Deployment）就是把你做好的教学工具"上传到互联网"，让学生通过一个链接就能使用，不需要安装任何软件。就像把你的课件传到云上，学生打开链接就能看到——只不过这个"课件"是交互式的、能打分、能记录成绩的教学工具。

    最重要的是：AI 会帮你完成大部分部署工作，你只需要告诉 AI "我想分享给学生"，然后按 AI 的指导操作几步就好。

    ⏰什么时候需要部署？

    🌐 场景一：生成链接发给全班学生（最推荐）

    你的教学工具做好了，想让全班学生都能访问。GitHub Pages 是最简单、最免费的方案——把你的项目文件夹变成网站，生成一个可以用浏览器打开的链接。

    💬 告诉 AI 的话（复制后按需修改）🌱 零基础
    我做了一个教学工具，项目在 [你的项目路径]。我想把它分享给我的学生使用。请帮我部署到 GitHub Pages，生成一个在线链接。我还没有 GitHub 账号的话，请先指导我注册。部署完成后告诉我链接是多少，我好发给学生。
    只要三步：告诉 AI → 按指导操作 → 拿到链接发给学生
    🇨🇳 场景二：在国内部署，访问速度更快

    如果你的学生主要在国内，GitHub Pages 可能加载稍慢。腾讯云静态网站托管是一个不错的选择——国内访问速度快、有免费额度、支持自定义域名。

    💬 告诉 AI 的话（复制后按需修改）🌿 简单概念
    我的教学工具项目在 [项目路径]，学生在中国大陆访问。请帮我把这个项目部署到国内可以快速访问的平台（比如腾讯云静态网站托管），并告诉我如何让学生访问。我还没有腾讯云账号，请先指导我注册。
    国内部署可能需要实名认证，提前准备好身份证信息
    🖥️ 场景三：打包成电脑应用程序

    如果你的工具需要离线使用、或者学生不方便联网，可以把网页工具包装成 Windows/Mac 可以安装的应用程序。就像把课件打印装订成册发给学生。

    💬 告诉 AI 的话（复制后按需修改）🌳 进阶运用
    我想把这个网页教学工具 [项目路径] 打包成一个可以双击打开就能用的桌面应用程序，支持 Windows 系统。请帮我完成打包，并告诉我生成的安装文件在哪里，怎么发给学生安装。
    桌面应用更适合离线使用场景
    📦
    部署方案一览

    GitHub Pages（推荐）— 完全免费，全球访问，AI 全程指导
    腾讯云静态网站托管 — 国内速度快，有免费额度，需实名认证
    Vercel / Netlify — 国际平台，连接 GitHub 自动部署，免费额度充足
    桌面应用（Tauri）— 离线可用，适合无法联网的场景

    不确定选哪个？直接告诉 AI："我想让学生用上这个工具，学生都在国内，帮我推荐最简单的部署方案"，AI 会帮你判断。
